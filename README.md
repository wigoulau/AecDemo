# AEC Demo · WebRTC 回声消除测试台

基于 WebRTC APM（`libs/webrtc_apm`）的可独立运行 AEC 验证工具。支持
**离线仿真 / 输入音频文件 / 设备实测 / 参数横向对比**，带 WebUI，
Windows、macOS、Linux（x64 / arm64，含树莓派）通吃。

## 快速开始

```bash
cd aecdemo
pip install -r requirements.txt
python run.py                 # 打开 http://127.0.0.1:8770
python run.py --selftest      # 只检查环境与 APM 动态库
python run.py --simulate      # 无界面跑一次离线仿真，结果在 output/
```

Windows 也可直接 `start.bat`，Linux/macOS `./start.sh`。

## 四种测试模式

| 模式 | 是否需要硬件 | 能测出什么 |
|---|---|---|
| **离线仿真** | 否 | 程序合成 mic/ref，已知回声与近端真值 → 可算 ERLE、近端保留率 |
| **音频文件** | 否 | 你已有的两路录音（L/R 或两个 WAV），看 AEC 对它们的效果 |
| **设备实测** | 麦克风 + 扬声器 | 真正跑一遍：程序播参考音 + 你说话，采集后做 AEC |
| **参数对比** | 否 | 同一输入横向比 5 种预设 × 多个延迟设定 |

### 离线仿真（推荐先跑这个）
- 时间轴自动分成 5 段：静音底噪 / 纯回声 / 双讲 / 仅近端 / 尾部静音
- 参考信号默认「类语音」——连续扫频会让 WebRTC AEC 一直重收敛，测出来很差，这是信号
  特性而非实现问题；界面上也保留了扫频选项用于观察
- 指标里 **ERLE（纯回声段）** 才是 AEC 的真实能力；双讲段 ERLE 必然低，因为人声本就不该被消

### 音频文件
两种给法，同一时间轴即可：

**① 一个多声道文件（推荐）** — 一个 `.wav` 里一路 mic、一路 ref，按声道拆开：

| 声道组合 | 说明 |
|---|---|
| ch1 = mic, ch2 = ref | 常见录制格式，也是本工具输出 `aec_in.wav` 的布局 |
| ch1 = ref, ch2 = mic | 若你的录音反过来，界面上把两个下拉互换即可 |

界面上选「一个双声道文件」，指定哪个声道是 mic、哪个是 ref。选完会显示检测到的
声道数，声道不足 2 或索引越界会直接报错。3/4 声道文件也可以，只取你选的两路。
`output/<...>/aec_in.wav` 可以直接拖回来当输入。

**② 两个单声道文件** — `mic_file` + `ref_file`，各自一路：
- `mic` = 麦克风录到的（含扬声器回声）
- `ref` = 那一刻扬声器实际播放的信号

两种给法的结果完全一致（走的是同一段 AEC 与指标代码）。勾选「自动估计延迟」可以
不必手工填延迟。

> 单声道文件不能用在单文件模式——程序不会替你猜哪一路是 mic。旧版本会把多声道文件
> 静默降混成单声道（两路平均），这个行为已移除，现在按声道精确取用。

命令行：

```bash
python run.py --files --mic mic.wav --ref ref.wav
python run.py --files --file rec_2ch.wav --mic-channel 0 --ref-channel 1
```

### 设备实测
1. 勾选「允许播放参考音」并二次确认（**不勾选不会打开扬声器**）
2. 选择输入/输出设备与采样率（USB 声卡默认 48k 就用 48k）
3. 选参考音来源：

   | 来源 | 用途 |
   |---|---|
   | 类语音（合成） | 默认，TTS 风格的连续语音，最接近真实播报 |
   | 短扫频突发 | 宽带激励，便于观察 AEC 收敛速度 |
   | 连续扫频 | 只用于观察「持续重收敛」现象，ERLE 会很低 |
   | **音频文件** | 上传一段真实 TTS / 音乐 / 录音，**推荐**——贴近线上实际播放内容 |
   | 静音 | 只录底噪，用于测本底与麦克风底噪 |

4. 点开始 → 程序先静音 0.3s，再播放参考音，同时录音
5. 播放期间**正常说话**（双讲场景最重要），结束后等 AEC 跑完
6. 听 `aec_out.wav`，对比 `mic.wav` 判断残余回声

选「音频文件」时，程序会**把文件完整播放一遍**并保存实际送出的信号到 `ref_played.wav`：
- 文件比「录音时长」长 → 播放完整文件，录音随之延长
- 文件比「录音时长」短 → 播完后继续录静音直到满足时长

播放前统一加 0.3s 前置静音、结束后留 0.4s 尾部静音，给 AEC 收敛与拖尾观察留余量。
`ref.wav` 保存的是同一份播放信号（已含增益与补零），所以它和 `mic.wav` 严格同长、同一时间轴。

设备模式下没有近端真值，只能看整体抑制量与主观听感；要定量请用仿真/文件模式。

> 注意：笔记本内置扬声器 + 内置麦克风的耦合是「近场 + 强非线性」，任何 AEC 都很难做干净。
> 验证算法请用外放音箱 + 麦克风保持一定距离，或用耳机避免物理回声。

## 输出产物

每次运行在 `output/<时间戳_任务ID>/` 下生成：

| 文件 | 说明 |
|---|---|
| `aec_in.wav` | **AEC 前的两路合轨**，L=mic，R=ref |
| `mic.wav` / `ref.wav` | 两路分开保存 |
| `aec_out.wav` | **AEC 后**的上行信号 |
| `ref_played.wav` | 设备模式实际送进扬声器的信号（含增益、前置/尾部静音，便于核对播放内容） |
| `near_truth.wav` | 仿真时的近端人声真值（算保留率用） |
| `metrics.json` | 分段指标、配置快照、引擎统计 |
| `plot.png` | 波形 + 逐 50ms ERLE + 纯回声段频谱对比 |

## 指标口径

- **ERLE（Echo Return Loss Enhancement）**：`10·log10(P(mic)/P(out))`，纯回声段的值才代表 AEC 能力。
  参考量级：仅 AEC 收敛后 25–35 dB，加 NS 后 35–50 dB。
- **近端保留率**：仅近端人声段落里 `10·log10(P(out)/P(near_truth))`。0 dB 左右说明人声没被吃掉；
  明显为负说明 AEC/NS 在误伤近端（双讲能力不足）。
- **回声耦合损耗**：`ref → mic` 的能量比，反映物理回声有多强，与算法无关。
- **实时因子 RTF**：处理耗时 / 音频时长，< 1 才能实时。普通 PC 上 16k 约 0.02–0.05。

## 处理内核约束

| 模块 | 职责 |
|---|---|
| [aec_demo/apm.py](aec_demo/apm.py) | ctypes 绑定 `libs/webrtc_apm`，相对本项目 `libs/` 加载 |
| [aec_demo/aec.py](aec_demo/aec.py) | near/far 双流、10ms 分帧、延迟估计、逐帧统计 |
| `libs/webrtc_apm/` | 动态库，含 win/macos/linux × x64/arm64 |

三条硬约束：APM 只吃 10ms 帧；每帧 near 前必须已喂入对应 far；
far 采样率不同时用 soxr 流式重采样；处理失败即旁路，不中断链路。

**已知限制**：本仓库这套 `libwebrtc_apm` 动态库上，`echo.mobile_mode=True` 会让
`process_stream` 在第 2 帧返回 `-11`（参数非法），所有采样率与块大小下都会复现。
本 demo 会先探测、自动降级为桌面 AEC 并在结果里明确标注，不会静默失败。
所以「移动端模式」预设实际跑的是桌面 AEC。

## 跨平台

动态库按 `libs/webrtc_apm/<系统>/<架构>/` 自动选择：

- Windows: `windows/x64`、`windows/x86`
- macOS: `macos/x64`（Intel）、`macos/arm64`（Apple Silicon）
- Linux: `linux/x64`、`linux/arm64`（树莓派 4/5 64 位系统、Jetson 等）

树莓派注意事项：
- 用 64 位系统（`uname -m` 为 `aarch64`）；32 位 armhf 没有对应库
- `sudo apt install libportaudio2`（sounddevice 依赖）
- 无桌面环境时用 `--host 0.0.0.0` 启动，从另一台机器访问 WebUI
- 若外接 USB 声卡，设备列表里按名字选，别用「default」

## 常见问题

**APM 不可用** — `python run.py --selftest` 看具体路径；确认 `libs/webrtc_apm/` 下当前平台目录有动态库。

**ERLE 很低 / 没效果**
1. 延迟填错：用「自动估计延迟」或对比模式扫一遍
2. 参考信号是连续扫频/纯音：换「类语音」
3. 设备模式下扬声器音量太小或 mic 离得太远：回声低于底噪，AEC 无从下手
4. 强非线性（内置小喇叭开大音量）：失真超出线性自适应滤波能力

**设备模式报「需要显式允许播放参考音」** — 这是刻意的保护，防止在你不注意时突然出声。

**网页打不开 / 端口占用** — `--port 其他端口`。
